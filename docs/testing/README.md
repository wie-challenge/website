# Test scope and evidence

Run from the website root with Node 24 / pnpm 11.3.0 / Docker default context. Chromium is selected from `/usr/bin/chromium` or Playwright's installed browser; install with `pnpm exec playwright install chromium`. No sibling repository is required. Tests create/migrate/remove uniquely named disposable PostgreSQL 17.7 containers, capture SMTP locally and never accept production credentials as test-write or restore targets.

- `pnpm test`: 29 API + 5 web unit tests. Domain cases enumerate valid/invalid/unauthorized/terminal transitions for RFQ/order/offer/batch/payment, exact TND bounds/rounding, quantities, allocation, cumulative production, QA reconciliation, settlement, closure and deterministic property-style partitions. Existing identity/capacity/operations cases remain.
- `pnpm test:integration`: 54 actual PostgreSQL/Nest/Better Auth/SMTP scenarios. Commerce cases persist/reopen private drafts, accept exact quotes once, reconcile buyer funding, test concurrent capacity reservations, decline/expiry/reallocation, owner-only decisions, cumulative progress, failed QA totals, immutable/replayed inspections, consensual rework, shipment gates, exact separate buyer/artisan simulated ledgers, unpaid closure and audited completion. Existing session/RBAC/tenant/replay/outbox/upgrade tests remain. The real restore drill now compares all 31 public tables, including commercial state and payment history, by counts/content hashes in a second disposable database.
- `pnpm test:e2e`: 14 optimized Chromium browser tests. Two complete synthetic commerce journeys run at 360×800 and 1280×900; the mobile journey uses 4× CPU throttling, 150ms latency and constrained throughput. Actions run with keyboard activation and focus assertions, forms have associated labels, saved drafts reopen, server-committed responses are dropped/retried with the same key, QA errors are announced, reduced motion overrides inline animations and persisted fulfillment/money are asserted through the API. Existing 320px keyboard/skip-link, mobile identity, no-JavaScript, pending submission, network failure and organization/delegation/MFA tests remain.
- `pnpm test:e2e --grep 'signup, email verification, profile'`: focused disposable startup/authentication smoke using the same real setup, suitable for clean-source verification after dependencies install.
- `pnpm lint`, `pnpm typecheck`, `pnpm build`, `pnpm audit --audit-level=high`: actual static, production compilation and dependency checks.

Commerce fixtures are version **commerce-v1** in `apps/api/test/commerce.fixture.ts` (stable fictional identities/quantities/amounts; future deadlines are relative to execution time). Fixture seeding/control endpoints are imported only by test harnesses, never by the API application. The browser control server binds loopback with a random per-run nonce and is removed during cleanup. No real order or funds are used.

Axe 4.14.0 scans the main-content regions at buyer form, artisan decision, operator review and buyer fulfillment checkpoints with WCAG 2/2.1/2.2 A/AA tags, for both viewport profiles. The final Playwright JSON report is `.local/e2e-report.json` and includes each axe checkpoint's violations/passed-rule IDs plus synthetic persisted-result attachments. Captured operator screenshots are `.local/commerce-{mobile,desktop}-operator.png`; the mobile screenshot was visually inspected for clipping/readability. CI retains the targeted JSON/screenshots, integration log and failure traces for three days. No credentials/environment file is an artifact target.

These checks are evidence for the implemented critical journeys, not a complete WCAG certification, independent screen-reader evaluation, cross-browser claim or measurement of a physical low-end device. CPU/network conditions are explicitly **emulated**. Firmware/simulator/physical device evidence remains separate in `../firmware/README.md`.

Actual execution outcomes, including failed intermediate tests and clean-install/network limitations, are recorded in `../engineering/E16_TEST_RESULTS.md`; the three requested issues have their own acceptance mapping in `../engineering/E16_TARGET_STORIES_REPORT.md`.
